# Relay product icebox

Agreed 3 November 2026. These are deferred product expansions, not production-v1
commitments. Existing experimental code is not deleted or automatically enabled
for launch by this decision.

V1 promise: describe an outcome, compare eligible supplier offers, explicitly
authorize work, receive verifiable delivery and settle payment reliably. One
accountable supplier owns each task. Capability evidence, scoped permissions,
audit history, budgets and a practical dispute process remain foundational.

| Deferred expansion | Revisit when |
| --- | --- |
| Advanced requirements discovery | Actual briefs expose repeatable scoping failures |
| Full MCP supplier integration and expanded developer tooling | Independent API/SDK suppliers demonstrate a concrete need |
| Learned routing, geography/compliance matching and automatic purchasing | Reliable outcome data and explicit purchasing policies exist |
| Automatic decomposition, re-planning and paid multi-supplier orchestration | Single-supplier work exposes demand that justifies coordination and liability |
| Independent verification for arbitrary work | Narrow task-specific checks are validated and broader rubrics can be evaluated |
| Advanced reputation, SLA tiers and compliance programmes | Operating history and buyer requirements justify them |
| Global settlement coverage, crypto and complex billing | The initial payment setup, reconciliation and economics are proven |
| SSO/SCIM, procurement integrations and advanced vendor governance | Committed enterprise customers require them |
| Public buyer purchasing API | The underlying transaction is stable, with quotas and support capacity |
| Broad Relay-hosted apps and automations | Isolation, runtime cost, maintenance and support are validated; separately gated paid offering |

Recurring work stays narrowly controlled: explicit schedule, approved scope,
supplier, budget and permissions. A delivery never becomes recurring by itself.
Recommendations do not authorize spending. A supplier's completion claim is not
independent verification.

## Not in the icebox

Production correctness and security: trustworthy accounting and exports, role and
permission revocation, recovery, real sandbox payment reconciliation, connector
authorization/revocation, independent supplier validation, browser/mobile/
accessibility QA and independent security/payment/operations review. Follow
[V1 readiness](V1-Readiness.md) for execution order. Unit economics remain unproven;
local tests are not production certification.

### Explicit scope change — 5 November 2026

Buyer-reviewed parent plans with dependent subtasks are now implemented for
localhost unpaid execution. Independent steps may run concurrently, with explicit
accepted/versioned handovers. Automatic decomposition, re-planning and paid
multi-supplier settlement remain deferred. See the latest [readiness entry](V1-Readiness.md).
